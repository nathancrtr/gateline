intent-brief.md (as confirmed before staging — contracts/intent-brief.md's four sections)

Problem

The widget search results page loads every matching row in one response; result sets above ~500 widgets take 8-12s to render and the tab becomes unresponsive on lower-end machines. Support has logged two duplicate reports this month (#463, #479).

Motivation

Two customers have flagged the slow search as a blocker ahead of their Q3 renewal conversations. Support is manually asking customers to narrow filters as a workaround.

Constraints

  • Preserve the existing filter/sort query parameters across pages.
  • No new backend datastore — paginate against the existing search index.
  • Ship behind the existing search-widgets feature flag.

Out of scope

  • Redesigning the search filters themselves.
  • Infinite scroll (page-relative URLs were explicitly requested so results stay linkable).
