Specification: log rotator

A small, dependency-free log rotation module for the shared utilities package — sized to behave well under our real production load and to fail loudly on the edge cases we have actually hit.

Context

The shared utils.py writes log lines to a single rolling file. Today the file grows without bound; on a busy box it reaches several gigabytes before an operator notices. We have a cron job that compresses old logs nightly, but it does not rotate them, and it cannot truncate a file a running process holds open.

Two incidents this quarter trace to this: a disk filled on the ingest host, and a downstream parser choked on a half-written line that crossed a gigabyte boundary. Both would have been avoided by rotating at a sensible size and writing a fresh handle.

This spec covers the rotation behavior only — not compression, not shipping, not retention policy. Those live in their own modules and their own gates.

Requirements

R1 — Rotate by size

  • AC1.1 — When the active log file exceeds the configured maxBytes, the module closes the current handle, renames it with a numeric suffix, and opens a fresh file at the original path.
  • AC1.2 — Rotation is atomic from the writer's perspective: no log line is lost or duplicated across the rename.
  • AC1.3 — maxBytes defaults to 10 MiB and must be configurable to any value ≥ 1 KiB.

R2 — Bound the backlog

  • AC2.1 — The module keeps at most backupCount rotated files; older rotated files are unlinked. When backupCount is zero, rotated files are deleted immediately.
  • AC2.2 — A rotation that would exceed backupCount unlinks the oldest file first, then renames. Ordering is preserved under concurrent rotations.

Assumptions

ASSUMPTION: the log path lives on a local filesystem with POSIX rename semantics. Network mounts and object stores are explicitly out of scope; a later run may add a sink abstraction.
The point of a rotator is not to be clever — it is to fail predictably. If two rotations race and we lose a file, the operator should be able to say exactly which one and why. — from the ENG-421 thread, linear-issue

Behavior sketch

# rotate(path, max_bytes=10*1024*1024, backup_count=5)
def rotate(path, max_bytes, backup_count):
    if path.stat().st_size < max_bytes:
        return            # nothing to do
    for i in range(backup_count, 0, -1):
        src, dst = path.with_suffix(f".{i-1}"), path.with_suffix(f".{i}")
        if src.exists(): src.rename(dst)
    path.rename(path.with_suffix(".0"))
    path.touch()

Out of scope

  • Compression of rotated files (separate module, separate gate).
  • Shipping logs to a remote sink; this run writes to the local filesystem only.
  • Retention policy beyond backupCount; age-based expiry is a later concern.
  • Async or threaded rotation; the writer calls rotate() synchronously.
