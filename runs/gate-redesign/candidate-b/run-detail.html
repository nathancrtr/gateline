Specification: log rotator

Context

The service currently writes diagnostic logs to a single directory without bounds. On long-running hosts this has twice filled the disk and caused the host orchestrator to evict healthy pods. We need a small, auditable behavior that rotates logs by age and total size while preserving the existing log format so downstream log shipping keeps working.

The rotation should be explicit and reversible: no background threads, no magic filenames, and no reliance on host tooling such as logrotate. The agent must implement the rotation as pure Python in src/core.py so it can be unit-tested.

Operational note: the on-call runbook should never again require SSHing into a host to delete *.log files by hand.

Requirements

R1 — Rotate by age

When a log file reaches 24 hours of age it must be closed, renamed with an ISO-8601 suffix, and a new log file opened. The rename target must sort lexicographically so a simple directory listing reveals order.

  • AC1.1 — A file older than 24h is rotated before the next write.
  • AC1.2 — The rotated name is {base}-{timestamp}.log with UTC timestamp.

R2 — Enforce a total size cap

The directory must never exceed the configured cap across all *.log files. Oldest archives are deleted first, with each deletion logged through the same structured logger that produced the rotated file.

def enforce_cap(directory: Path, cap_bytes: int) -> None:
    """Remove oldest archives until total size is at or below cap_bytes."""
    archives = sorted(directory.glob("*.log"), key=lambda p: p.stat().st_mtime)
    while sum(a.stat().st_size for a in archives) > cap_bytes and archives:
        oldest = archives.pop(0)
        logger.info("Pruning old archive", path=str(oldest))
        oldest.unlink()
  • AC2.1 — Cap exceeded by one byte triggers at least one prune.
  • AC2.2 — The active log is never deleted to make space.

Assumptions

ASSUMPTION: The host filesystem supports atomic rename within the log directory, and the process holds an exclusive lock on the active log during rotation.

Out of scope

  • Compression of archived logs.
  • Remote shipping of archived logs to S3 or another store.
  • Log tailing, search, or indexing.
  • Windows-specific path handling beyond standard pathlib.
