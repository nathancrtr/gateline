…but one grammar — the same family FleetView's gate decisions already speak

  • Every act lands as an attributable commit, authored by the server's git identity — displayed, never typed.
  • Refusals are first-class: missing sections, no identity, collision, replay — each names its cause and its fix, reusing the Flash ok / conflict / error triad plus one informational tone.
  • A concurrent move re-presents (409), never auto-retries — the same posture DecidePanel already takes.
  • Both acts ride one write path: stageRun for staging, POST /api/decisions {action:'arm'} for arming. No parallel mutation route, no new nav.
